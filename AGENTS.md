# AGENTS.md

## Purpose

This is a documentation-first repository for practical notes, tips, and reminders for GitHub employees preparing to leave the company.

## Repository shape

- `README.md` is the main document and should remain the primary entry point.
- Prefer a small number of focused supporting Markdown files only when the README becomes hard to navigate.
- Do not introduce an application, package, build system, or documentation framework unless explicitly requested.

## Writing guidelines

- Write for employees taking concrete steps before or shortly after departure.
- Keep guidance concise, practical, and easy to scan.
- Prefer headings, short paragraphs, bullet lists, and clear checklists.
- State important deadlines, eligibility limits, and tradeoffs when they are publicly verifiable.
- Distinguish between steps that apply broadly and those that depend on location, employment terms, or individual benefits.
- Avoid financial, legal, tax, or benefits claims without reliable support; direct readers to the appropriate plan provider or professional when needed.
- Preserve the existing voice unless asked to rewrite it.

## Accuracy

- Verify links, product names, deadlines, eligibility rules, and benefit claims before adding them.
- Do not invent policy details, migration steps, or access instructions.
- Note when guidance depends on location, departure date, plan terms, or employment status.
- Prefer public primary documentation as a source. Add inline links where they help readers verify or continue.
- Never include real credentials, private repository details, or personal data in examples.

## Public-information boundary

- Treat every contribution as public, even if the repository's visibility changes.
- Do not publish internal links, private repository names or contents, non-public screenshots, confidential policies or benefit documentation, employee-only access instructions, credentials, or personal data.
- Do not turn information from private conversations into attributed quotes without permission.
- Generalize useful internal tips into publicly safe advice. For example, say to save permitted personal employment records rather than naming a private system or repository.
- When unsure whether something is public, leave it out and ask the repository owner before adding it.

## Changes

- Keep edits narrowly scoped to the requested topic.
- Avoid reorganizing unrelated content while adding a tip or section.
- Use relative links for files within this repository.
- Check that Markdown renders cleanly, links are valid when practical, and code blocks specify a language where appropriate.
- There is currently no build or test suite; review the rendered Markdown and inspect the diff before considering a change complete.
